# 线下聚会 VRChat 身份牌设计

日期：2026-08-07
状态：设计已确认，等待书面评审

## 1. 背景

VRChat 好友线下聚会时，参与者常把显示自己 VRChat 照片的手机摆在一起合影。普通照片缺少 Display Name 和身份信息，VRChat 官方 App 又存在体积、地区下载和自定义能力方面的限制。

VRCM 增加一个以手机为主要场景的全屏身份牌：照片是视觉主体，Display Name 始终可识别，用户可以选择展示资料字段、二维码和当前装备的 VRChat 官方 Profile Decoration。身份牌必须离线优先，不能因现场弱网进入空白或加载页。

## 2. 目标

- 从首页快速进入适合合影的全屏身份展示。
- 支持资料背景图、手机相册和 VRChat Gallery 三种照片来源。
- 提供三套稳定模板，而非自由画布编辑器。
- 支持竖屏和横屏，允许分别调整裁剪，并可为横屏设置独立照片（未设置时沿用竖屏照片）。
- 所有可选资料字段、二维码和官方装饰均可独立控制。
- 完成首次配置后，即使网络不可用也能立即展示上次有效内容。
- Android、iOS 完整支持；Desktop 支持编辑和预览。

## 3. 非目标

- 不生成或导出静态海报、视频或社交媒体素材。
- 不提供文字、头像或二维码的自由拖动与缩放。
- 不上传本地照片、自定义短句或身份牌配置到 VRChat。
- 不提供自定义二维码链接，二维码只指向当前用户的公开 VRChat 主页。
- 不提供用户可见的官方装饰下载、导出、编辑或重新打包能力；仅允许展示所需的应用私有运行时缓存。
- 不在首版提供多套身份牌预设、活动共享模板或云同步。

## 4. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 核心产物 | 现场全屏展示模式 |
| 首页入口 | 单击头像保持进入个人资料；长按头像进入身份牌 |
| 默认模板 | 资料栏 |
| 其他模板 | 聚光、侧签 |
| 照片来源 | 资料背景图、手机相册、VRChat Gallery |
| 屏幕方向 | 竖屏和横屏自适应 |
| 数据策略 | 离线先显示，上线后后台刷新 |
| 控制层 | 默认隐藏，轻点临时显示返回与编辑 |
| 屏幕状态 | 展示期间保持常亮，不修改亮度 |
| 二维码 | 可选的 VRChat 个人主页二维码，默认关闭 |
| 官方装饰 | 头像框、资料特效、铭牌特效可独立关闭 |
| 平台 | Android、iOS 完整支持；Desktop 可编辑和预览 |

## 5. 用户流程

### 5.1 首页入口

首页头像使用可区分单击与长按的交互：

- 单击继续打开现有本人资料页，不改变共享元素 key 和现有返回动画。
- 长按时若已完成首次配置（用户提交过编辑或换过照片），直接导航到身份牌展示页。仅打开过编辑页而未做任何改动不算完成，避免用户被直接带到一张空卡。
- 长按时若是首次使用，以当前资料背景图、资料栏模板和仅显示 Display Name 的默认配置打开编辑页。
- 长按防抖；当前路由已经位于身份牌或编辑页时不重复入栈。
- 首页的“头像 + 名字/状态”一组与整张铭牌登记为同一共享元素，进出铭牌页时由它承担主体形变；展示页与编辑页预览沿用同一 key，三者构成连续形变链。屏幕级转场只做淡入淡出，避免与共享元素叠加成双重缩放。
- Desktop 使用相同入口：鼠标按住头像触发长按语义，不新增独立按钮。

### 5.2 编辑

编辑页包含实时预览和四个工具页：

1. **照片**：资料背景图、手机相册、VRChat Gallery；选择后进入裁剪。
2. **布局**：资料栏、聚光、侧签；竖屏与横屏分别保存各自版式，改动作用于预览中选中的方向。
3. **内容**：头像、人称代词、语言、状态、状态描述、自定义短句和二维码开关。
4. **样式**：主题色、遮罩强度、头像框、资料特效和铭牌特效开关。

工具页内的控件按语义分组，每组为"标题 + 圆角容器"。主题色作用于模板前景而非仅底层背景（照片会盖住底层）：无官方铭牌装饰时铭牌底色、资料面板底色、聚光与侧签的遮罩渐变都带主题色。

竖屏/横屏使用分段控件切换预览。两个方向保存独立裁剪参数；首次生成另一个方向时，以同一焦点和 cover 规则生成安全默认值，用户可继续微调。选择照片时可指定应用方向：双方向共用、仅竖屏或仅横屏；横屏独立照片未设置或不可用时回退竖屏照片。

编辑页不提供单独的保存按钮。模板、开关和文本等离散操作立即提交；裁剪和滑杆在手势结束时提交；页面离开前刷新一次持久化状态。持续拖动期间只更新内存草稿，避免高频磁盘写入。

编辑预览按页面内容区尺寸（Desktop 上不含自绘标题栏）等比缩放，保证与展示页构图一致。编辑页在 Expanded 宽度类下左侧预览、右侧固定宽度设置栏并列显示，其余宽度类为上预览下设置的单列布局。展示页整卡与编辑页预览登记同一共享元素，进出编辑页时整卡在全屏与预览缩略图之间连续变换；变换使用等比缩放而非重新测量，避免模板在动画中途重排。

### 5.3 展示

- 照片、装饰、身份信息和控制层由 Compose 实时分层渲染，不预生成海报位图。
- Display Name 始终显示，其他字段均可关闭。
- 手机端进入沉浸式显示并保持屏幕常亮，但不修改屏幕亮度。
- Desktop 填满应用内容区，不强制切换操作系统全屏。
- 控制层默认隐藏。轻点显示返回、编辑和当前方向信息；无进一步交互 3 秒后淡出，新的触摸或指针活动重新计时。
- 系统返回始终退出展示；重复点击返回或编辑不会产生重复导航。
- 离开展示、应用进入后台或页面异常销毁时恢复系统栏和常亮状态。

## 6. 模板

三套模板共享相同数据和开关，只定义稳定的信息槽位。模板根据方向提供竖屏和横屏布局，不通过按视口宽度缩放字体。

### 6.1 资料栏（默认）

照片与信息区域明确分区。它能稳定容纳较多字段和二维码，是首次使用的默认模板。

### 6.2 聚光

照片全屏铺设，身份信息位于底部高对比遮罩上。它优先保证合影中的远距离识别。

### 6.3 侧签

主要信息沿侧边竖向集中，保留中央主体区域。它适合主体位于照片中央的构图。铭牌版式为 Column(头像, Row(人称代词, 名字))：头像在上保持正脸，人称代词与名字两段文字各自顺时针旋转 90 度成并排的竖排文字；横版铭牌特效素材同样旋转铺满。竖排文字高度上限为侧栏高度的 55%，字段、短句与二维码在其下方依次竖排。

资料栏与聚光模板中，铭牌独占整行，状态、状态描述等文本与二维码作为同一 Row 的同级子元素并列。

Display Name 使用模板允许范围内的动态字号与最多两行布局，最长单词也不得溢出。可选字段按模板定义的优先级换行，不得覆盖名字、二维码或相邻内容。状态与状态描述以文本字段形式呈现，不复用在线列表的彩色状态点。自定义短句限制为 80 个 Unicode code point、最多两行；编辑器在超限时阻止提交并显示本地化错误。

## 7. 架构

### 7.1 页面和状态

新增身份牌展示 `AppRoute` 和编辑 `AppRoute`，继续使用 Navigation 3、Lifecycle ViewModel 和 Koin。

身份牌 ViewModel 对外只暴露一份 `StateFlow<MeetupCardUiState>`。Composable 负责展示、手势和导航编排，不直接访问 Network、Storage 或平台系统控制器。

`MeetupCardRepository` 负责：

- 读取和写入当前账号的配置与资料快照。
- 协调照片来源和应用私有素材。
- 先返回本地可展示状态，再刷新当前用户资料和官方装饰。
- 使用账号 generation 丢弃登出或切换账号后的过期结果。
- 将部分失败转换为明确状态，而不是吞异常或伪装整体成功。

### 7.2 建议的数据边界

持久配置按 VRChat 用户 ID 隔离，包含：

- schema version 和 owner user ID。
- 模板、主题色与遮罩强度。
- 内容和三个官方装饰的开关。
- 自定义短句与二维码开关。
- 照片来源描述、当前本地素材引用。
- 竖屏和横屏裁剪参数。
- 上次有效资料快照。

资料快照包含 Display Name、头像 URL、人称代词、由 `language_*` tags 推导的语言、状态和状态描述。外观快照独立保存由 Profile endpoint 返回的三个已装备官方装饰 Template ID。两种快照都是离线展示数据，不是第二个可编辑资料源；对应网络刷新成功后才整体替换。

配置 JSON 沿用现有 Multiplatform Settings + kotlinx.serialization 模式，并设置 `ignoreUnknownKeys` 与 schema version。大图片和动画字节不写入 Settings 或数据库。

迁移策略：不做字段级迁移。数据结构发生不兼容变化时提升 `MEETUP_CARD_SCHEMA_VERSION`，DAO 把旧版本配置一律按"不存在"处理，用户重新配置一次。这比让 `ignoreUnknownKeys` 把被改名的字段静默丢成默认值可控——那样用户会发现某些设置莫名变回默认却没有任何提示。

### 7.3 素材存储

新增应用私有 `MeetupCardAssetStore`，元数据与文件写入遵循以下规则：

- 选中任一照片来源后，将原始图片复制到应用私有目录，再切换配置引用。
- 写入使用同目录临时文件、校验和原子替换；失败时保留上一份有效素材和配置。
- 本地相册图片属于用户配置，不随普通网络缓存清理而删除。
- 资料背景图和 Gallery 照片保留来源 ID/URL 供刷新，但展示不依赖远端或 Coil 临时缓存。
- 官方装饰素材按 Template ID 和 asset type 缓存；普通缓存清理可以删除远端装饰副本，但不得删除身份牌配置或用户从相册选择的私有图片。
- 移除账号时删除其配置与私有图片，并释放其装饰引用；没有其他账号引用的装饰缓存可以清理。

平台私有目录通过现有源集风格的窄平台接口提供，路径判断不散落在 `commonMain`。

### 7.4 图片选择与裁剪

- 手机相册继续使用 FileKit。
- Gallery 增加选择模式；通过内存 session store 返回选择结果，Navigation 3 路由中不序列化图片字节。
- 复用现有图片读取、格式校验、预览解码和裁剪计算能力，但不把身份牌强行接入 Print/Avatar 的网络提交器。
- 身份牌保存原始私有图片和标准化裁剪参数，展示时按实际方向实时裁剪。

## 8. 官方 Profile Decoration

### 8.1 Profile endpoint

装饰 ID 不加入现有 `UserData`。新增独立的 Profile Appearance API：

```text
GET /profile/{userId}?asSelf=true&withGroupsAndWorlds=true
```

响应 DTO 只解析 `id` 和以下可空且有默认值的字段，避免缺少字段的响应反序列化失败：

- `iconFrame`
- `profileEffect`
- `nameplateEffect`

字段值只表示当前装备的 Inventory Template ID。响应 `id` 与请求用户不一致时整份外观结果无效；单个字段缺失表示本次响应不更新该字段，显式空字符串表示该槽位未装备装饰。注意：JSON 显式 `null` 与字段缺失在解析层不可区分，均按"保留旧值"处理；若线上 API 以显式 `null` 表达"未装备"，需实测后调整该假设。

### 8.2 Template API

新增独立 Inventory API：

```text
GET /inventory/template/{templateId}
```

响应 DTO 只解析 `id`、`metadata.assets`、`metadata.gradientStart` 和 `metadata.gradientEnd`。相同 Template ID 在一次刷新中去重，并按 Template ID 共享持久缓存。

素材解析规则与 VRCX-0 一致：

1. `mainAnimation` 是持续循环动画的首选资源。
2. `base` 是动画离线、下载失败或解码失败时的静态兜底。
3. `introAnimation` 不在持续身份牌中播放。
4. `mainAnimation` 和 `base` 都不可用时关闭单个装饰并保留明确降级状态。

### 8.3 渲染

- `iconFrame` 固定包围头像。
- `nameplateEffect` 与渐变包裹整个铭牌块——横排为 Row(头像, Column(名字, 人称代词))，与 VRChat 铭牌结构一致；侧签为 Column(头像, Row(人称代词, 名字))，两段文字各自旋转 90 度竖排，横版特效素材同样旋转铺满，头像保持正脸。没有官方装饰时铭牌用主题色打底，前景色按底色亮度选取。
- `profileEffect` 顶部对齐、铺满卡片宽度并按素材纵横比等比缩放，超出高度部分裁剪，不拉伸。
- 装饰层不接收指针事件，不改变身份牌控件布局。

动画播放器是平台能力接口，目标是在 Android、iOS 和 Desktop 播放官方 animated WebP。优先复用成熟的平台/图片库解码能力，不手写 WebP 解码器；具体平台解码失败时才使用已缓存 `base`，不能把某个平台永久缺少动画支持当作正常完成状态。

播放器跟随页面生命周期：前台播放、后台暂停、离开释放帧资源。三个 Template 请求和资源加载不阻塞照片与 Display Name 首屏。

## 9. 二维码

二维码内容固定为：

```text
https://vrchat.com/home/user/{userId}
```

二维码默认关闭，完全在本地通过成熟的 Kotlin Multiplatform 二维码编码库生成，不使用远端生成服务、不添加跟踪参数，也不支持自定义链接。二维码区域具有稳定尺寸和安静区，在窄屏或大字体下不能被其他字段挤压或覆盖。

VRCM 在 Android 注册为 `vrchat.com/home/user/*` 与自定义 `vrcm://user/{userId}` 链接的处理者。由于 Android 12+ 对未验证域名的 https 链接不弹应用选择器（vrchat.com 无法配合放置验证文件），编辑器提供二维码链接类型选项，两种内容都固定指向当前用户、不接受自定义：

- **VRChat 主页（通用，默认）**：任何设备可扫，装有 VRChat 官方 App 的设备会跳其应用内主页；VRCM 需用户在系统设置中启用链接接管。
- **VRCM 直达**：`vrcm://user/{userId}`，装有 VRCM 的设备扫码必定直接进入应用内用户详情页（未登录时先完成登录再跳转）；未安装 VRCM 的设备无法打开，适合参与者都使用 VRCM 的聚会。

两种类型可同时选中并列展示，至少保留一项。同时展示两个码时，各自在白底安静区内附一行短标识（VRChat / VRCM）以便区分；只有一个码时省略标识，让码本身更大。

iOS 因 Universal Links 需要 vrchat.com 域名配合，暂不支持拦截 https 链接。

## 10. 离线刷新顺序

进入身份牌时按以下顺序工作：

1. 读取当前账号配置、资料快照和本地图片。
2. 立即构造可展示 UI state；不得等待网络或官方装饰。
3. 并行刷新本人常规资料与 Profile Appearance；继续用外观快照中的 ID 读取本地 Template 缓存。
4. Profile Appearance 返回新的 Template ID 后，去重请求对应 Template 元数据。
5. 下载发生变化的资料来源图片和装饰资源到临时文件。
6. 验证账号 generation、响应用户 ID、文件和 revision 后，分别原子提交新的资料快照、外观快照与素材引用。
7. 失败分支保留上一份有效状态，并向编辑页暴露可本地化的刷新结果。

如果用户在刷新期间更换照片或修改字段，远端刷新只能更新资料快照和对应远端来源，不得覆盖更新开始后产生的本地编辑 revision。

## 11. 异常与状态

身份牌的最低可展示状态是主题背景加完整 Display Name。照片失效时依次尝试：

1. 重新打开当前私有素材。
2. 若来源允许且在线，重新下载来源。
3. 使用上次缓存的资料背景图。
4. 使用主题背景。

其他异常规则：

- Gallery 无 VRC+、无内容或请求失败时，资料背景图和本地相册仍可使用。
- 新图片格式不支持、文件过大或解码失败时保留上一张有效图片。
- 单个官方装饰失败只降级该装饰。
- 配置或素材写入失败时保留上一 revision，并显示明确错误。
- Display Name、照片和二维码各自具有稳定布局占位，加载状态不得推动其他元素跳动。
- Loading、empty、error、disabled 和重复点击状态均需明确处理。

## 12. 平台与生命周期

共享 UI、状态、网络 DTO、配置和业务规则位于 `commonMain`。只有以下能力使用窄平台接口：

- 应用私有素材目录。
- 沉浸式系统栏控制。
- 屏幕常亮控制。
- animated WebP 解码能力中确有平台差异的部分。

平台控制器使用获得/释放式 API，并在 `DisposableEffect`、ViewModel 清理和应用后台事件中幂等恢复。不得使用固定延迟掩盖生命周期竞态。

## 13. 隐私与安全

- 本地照片、自定义短句、裁剪和开关只存储在应用私有空间。
- 身份牌不会调用 VRChat 上传接口。
- 只请求当前用户资料声明的装饰 Template，不枚举或打包官方素材。
- API 和素材 URL 通过现有认证、重试和 Ktor client 边界处理，不创建平行网络客户端。
- 路由和日志不包含图片字节、认证信息或本地绝对路径。

## 14. 多语言与无障碍

- 所有用户可见文案进入现有 `LocaleStrings`，同步英文、日文、简体中文和繁体中文。
- 控件使用项目 `AppIcons` 和语义化 content description。
- 模式选择使用分段控件，字段使用开关，遮罩使用滑杆，照片来源和 Template 使用明确的选择控件。
- 编辑器支持系统字体放大；模板保证 Display Name 完整可读，文字不得互相遮挡。
- 官方动画可以通过三个装饰开关关闭；关闭后仍保留静态模板结构。

## 15. 测试策略

新增测试只覆盖会在编译通过时仍可能回归的行为：

- 配置按账号隔离、schema 兼容和旧缓存读取。
- 临时文件校验、原子替换失败与上一 revision 保留。
- 缓存先展示、后台刷新成功/失败以及账号切换后的过期结果丢弃。
- 刷新与本地编辑并发时，本地 revision 不被覆盖。
- 竖屏和横屏裁剪互不覆盖。
- Template ID 去重、部分请求失败和 `mainAnimation -> base -> 关闭` 降级链。
- Profile Appearance 响应用户不匹配、字段缺失保留旧值和显式空值清除槽位。
- 使用真实 animated WebP fixture 验证 Android、iOS、Desktop 播放生命周期和静态回退。
- 首页单击头像仍进入个人资料，长按才进入身份牌。
- Gallery 选择结果通过 session 返回，路由不携带图片字节。

不为颜色、透明度、尺寸、间距、简单 DTO 相等性或框架默认行为添加测试。模板视觉通过人工检查，不用低价值 Compose UI 断言复述 Modifier 或样式数值。

## 16. 验证

实现后至少执行：

```bash
./gradlew :composeApp:compileKotlinDesktop
./gradlew :composeApp:desktopTest
./gradlew :composeApp:assembleDebug
./gradlew :composeApp:linkDebugFrameworkIosArm64
git diff --check
git status --short
```

如果共享测试或平台动画改动的影响范围超出上述最小集合，再运行 `:composeApp:allTests` 或 `:composeApp:check`。

人工验证矩阵包含：

- Android 与 iOS 的竖屏、横屏、系统返回、后台恢复和常亮恢复。
- 三套模板在窄屏、横屏和大字体下无文字或控件重叠。
- 飞行模式下从首页长按到已配置身份牌，不出现空白或阻塞加载。
- 动画资源成功、动画失败静态回退、全部资源失败三个分支。
- Desktop 编辑、预览和图片选择。

## 17. 验收标准

- 首次配置后，用户可从首页长按头像进入身份牌；单击行为保持不变。
- 离线时能立即显示上次有效照片、完整 Display Name 和已缓存可选信息。
- 用户能从三种照片来源选择图片，并分别调整竖屏和横屏裁剪。
- 三套模板均支持所有字段开关，且资料栏是默认模板。
- 二维码只在用户开启时出现，并指向当前 VRChat 用户主页。
- 当前装备的三个官方装饰按规则显示；单个装饰失败不会影响身份牌主体。
- 退出或切到后台后，系统栏、常亮与动画资源恢复到进入前状态。
- 切换账号、登出和并发刷新不会串用配置、素材或资料快照。
