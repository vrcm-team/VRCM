# VRCM 1.1.2: What's New

**Languages / 语言 / 言語:** [English](1.1.2.md) · [中文](1.1.2_ZH.md) · [日本語](1.1.2_JP.md)

This document covers the main user-facing changes since `1.1.1`. This is a reliability and workflow release: it makes favorite content easier to manage, keeps Gallery edits predictable before upload, improves Android update delivery, and protects account state while realtime sessions and caches are changing.

The release is not a new collection of isolated list screens. It tightens the path from a saved world or avatar to the correct detail page, from a phone image to a finished Print, and from an expired session to a usable account again. Desktop and mobile packages also now carry the same release version and naming rules.

## Release scope at a glance

This release is best understood as four connected workflows:

1. **Keep saved content correct:** favorite worlds, avatars, and hidden entries follow the active account and refresh without stale requests overwriting the current state.
2. **Prepare images before sending them:** Gallery and Print editing now make border, crop, format, and output-size decisions visible before upload.
3. **Continue using the app when services change:** Android updates can fall back to mirrors, clipboard inspection is configurable, and expired realtime sessions can recover through authentication.
4. **Ship the same build everywhere:** Android, iOS, Desktop, and Windows installer metadata use the same version and release code.

## 1. Keep favorite content and caches aligned

### Favorite worlds and avatars

Favorite content is useful only when the favorite state, the group that contains it, and the detail page all describe the same account. VRCM 1.1.2 completes that path for favorite worlds and avatars:

- Open a world or avatar detail page and see whether the item is already favorited before choosing an action.
- Add an item to an existing group or the local group, then refresh the group list without losing the item that was just changed.
- Remove a favorite from the correct group even when several groups contain similar entries.
- Review hidden worlds and hidden avatars without mixing hidden entries into the visible favorite groups.
- Keep the favorite type explicit so a world ID cannot be applied to an avatar or friend cache.

The local group is an account-scoped convenience for entries that VRCM has observed locally. It does not claim to be a new VRChat server-side favorite group. Remote groups continue to use the VRChat favorite API and its account permissions.

### Account isolation and refresh behavior

Favorite and profile data can be requested at the same time as a user switches accounts or leaves a detail page. The release makes the ownership of each request explicit:

- A response from the previous account cannot replace the current account's favorite state.
- An empty target invalidates an in-flight load instead of allowing the old target to reappear.
- A failed favorite-state request is shown as a retryable state rather than silently becoming “not favorited.”
- Cached profiles keep live presence updates when a slower profile response arrives later.
- User profiles and created-world data can use incremental refreshes, reducing the amount of data replaced on every visit.

This is intentionally conservative. VRCM still refreshes from VRChat when the cache is stale or an action requires current server data; the cache is a starting point, not a second source of truth.

## 2. Edit Gallery images before uploading

### A visible Print and Polaroid workflow

Print images often need a deliberate composition rather than a direct file upload. The editor now keeps the important choices in one flow:

- Add a white border to a Print image when the source does not already contain the desired margin.
- Crop the Polaroid border while viewing the result, instead of uploading first and discovering the wrong framing afterward.
- Switch the crop behavior while editing and see the preview update with the selected mode.
- Use the correct output ratio for Gallery, Icon, Emoji, and Print targets rather than applying one shared rectangle to every category.

The editor keeps the source selection separate from the upload request. A user can cancel or go back before the final submission without creating a partial Gallery item.

### Format, transparency, and memory limits

The image pipeline now preserves the properties that matter for a result that will be used outside the editor:

- Preserve transparency when the selected output format supports it.
- Keep the requested format and category-specific output constraints when encoding the result.
- Reject unsupported formats, oversized files, and images beyond the pixel limit with an explicit failure.
- Decode and crop at a bounded size so a large source image does not occupy unbounded memory.
- Release intermediate bitmaps and preview resources after a crop or failed submission.

These limits are part of the upload contract. They prevent a preview from appearing valid when the final VRChat upload would be rejected, while still leaving the original source file untouched on the device.

### Upload and failure states

The Gallery screen now treats selection, preparation, upload, refresh, cancellation, and failure as separate states. After a successful upload, the active category refreshes so the new item can be checked immediately. A network error, permission error, unsupported format, or cancellation is reported as an error or cancellation instead of a false success.

## 3. Continue updates and links on Android

### In-app update downloads

Android update delivery now stays inside VRCM for the download step:

- The update dialog selects an APK asset for Android rather than exposing an unrelated package.
- The downloader checks the configured sources and can use a mirror when the GitHub endpoint is unavailable.
- Progress and cancellation are tied to the actual Android `DownloadManager` request.
- Failed or cancelled downloads clean up their temporary file and manager state, so a later update can start from a known state.

The mirror is a delivery fallback, not a replacement for the GitHub release. The downloaded APK still comes from the release asset selected by VRCM, and Android's normal package-install permission boundary remains in effect.

### Configurable clipboard inspection

Clipboard inspection is now a user setting and defaults to enabled for supported official VRChat URLs and IDs. VRCM still asks before navigating and only recognizes the supported VRChat formats; arbitrary clipboard text is ignored.

The inspection gate also tracks links that VRCM has just shared. Returning from the system share sheet no longer causes the app to treat its own copied URL as a new external link. Users who do not want clipboard inspection can turn it off without disabling manual search or direct navigation.

## 4. Recover a session instead of discarding it

### Expired realtime sessions

VRChat realtime sessions can expire while the app is in the background or while a network path is changing. VRCM now distinguishes a session rejection from a transient pipeline failure:

- An expired session can enter the existing authentication recovery flow and reconnect when the account is still valid.
- A temporary transport or pipeline error does not automatically erase the current account session.
- The WebSocket state reports the reason for rejection separately from an unexpected processing error.
- Foreground recovery can restore the live stream without rebuilding unrelated cached pages.

This does not bypass VRChat authentication. If the account requires a new login or the server rejects the credentials, VRCM reports that boundary and lets the normal login flow handle it.

### Lifecycle and notification details

Several smaller changes protect the same state contract:

- Friend sorting remains stable when a presence update arrives during a refresh.
- Cached profiles can receive live presence without being replaced by a late stale response.
- Notification timestamps describe receipt time rather than an unrelated render time.
- Room-card collapse and restore behavior is less likely to leave a stale animation state after a lifecycle transition.
- iOS restores the selected dark theme after returning from the background.

## 5. One release version across platforms

The release script now synchronizes the version catalog, Inno Setup, Xcode project settings, and the iOS `Info.plist`. The published 1.1.2 artifacts were built with the following metadata:

| Artifact | Version | Build code |
| --- | ---: | ---: |
| Android APK | 1.1.2 | 7 |
| iOS IPA | 1.1.2 | 7 |
| macOS Desktop DMG | 1.1.2 | 1.1.2 |
| Windows MSI / EXE installer | 1.1.2 | 1.1.2 |

Windows packaging keeps the MSI produced by Compose Desktop and can additionally produce `VRCM-v<version>-setup.exe` when Inno Setup is installed. The macOS package uses the VRCM application icon, and the artifact names are stable enough for release automation and update checks.

## 6. Platform differences and boundaries

| Capability | Android | iOS | Desktop |
| --- | :---: | :---: | :---: |
| Favorite world and avatar management | Yes | Yes | Yes |
| Gallery and Print editing | Yes | Yes | Yes |
| In-app APK update download | Yes | N/A | N/A |
| Clipboard URL/ID inspection | Yes | Yes | Yes |
| Realtime session recovery | Yes | Yes | Yes |
| macOS DMG packaging | N/A | N/A | Yes |
| Windows MSI/EXE packaging | N/A | N/A | Windows only |

The iOS artifact in this preview is ad-hoc packaged for direct testing. App Store distribution still requires the normal Apple signing, provisioning, and submission process. Windows EXE generation requires Inno Setup; the Desktop MSI task remains independent of that optional compiler.

## 7. Other notable fixes

These changes are smaller than the workflows above but affect repeated daily use:

- Corrected Gallery upload failures, animated-image handling, output ratios, and image-editor layout transitions.
- Corrected favorite removal targeting, detail-page favorite state, and cache invalidation after account switches.
- Corrected the Android update cancellation path and mirror fallback errors.
- Corrected the iOS dark-theme restoration path and Japanese friend-location text.
- Corrected self-shared clipboard prompts, notification display data, and several lifecycle transitions.
- Kept macOS icon and Windows installer naming consistent with the release version.

## Upgrading from 1.1.1

- The current application version is `1.1.2` with Android/iOS version code `7`.
- Existing accounts, favorites, and settings remain available. The first launch may refresh or migrate local caches.
- Favorite and profile caches are now separated more strictly by account. If a list looks incomplete immediately after upgrading, allow the first refresh to finish before repeating the action.
- Android users who want update downloads or system notifications should review the relevant notification, installation, and battery-management permissions.
- The iOS IPA and Desktop DMG in this GitHub preview are direct-install test artifacts, not an App Store submission or signed Windows EXE for every machine.
