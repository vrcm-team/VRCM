# VRCM 1.1.2: What's New

This release focuses on saved VRChat content, Gallery editing, update reliability, and the cache and session behavior behind everyday use. It also ships the first consistent Windows installer naming and versioning flow.

## Favorite content and cache management

Favorite worlds, favorite avatars, and hidden worlds now have complete management flows instead of being treated as separate list fragments.

- Favorite worlds and avatars can be loaded from account-scoped local caches for faster reopening.
- Hidden worlds and hidden avatars can be reviewed and removed without losing the rest of the favorite list.
- Favorite state on detail pages follows the active account and refreshes with the corresponding cache.
- Account switching, empty targets, and in-flight favorite requests are isolated so an old session cannot overwrite the current one.
- User profiles and created-world data use incremental cache refreshes where possible.

## Gallery editing and image handling

Gallery editing now covers the border and output workflows needed for mobile uploads and Prints:

- Add a white border to a Print or crop the Polaroid border in the editor.
- Adjust the crop while previewing the result instead of waiting for upload completion.
- Preserve transparency and the selected output format when processing images.
- Apply the correct aspect ratio for each Gallery category and release temporary image resources after processing.
- Keep upload, cancellation, refresh, and failure states separate so a failed operation is not shown as completed.

## Android updates and clipboard behavior

Android can now download an app update from inside VRCM. If the GitHub download endpoint fails, the update flow can fall back to a configured mirror. Cancellation is propagated through the download state instead of leaving a stale progress result.

Clipboard reading is configurable in Settings and is enabled by default for supported VRChat links. Links shared by VRCM itself no longer trigger an unnecessary self-share prompt.

## Reliability improvements

- Expired WebSocket sessions are recovered through the authentication flow when possible.
- Session rejection is distinguished from transient pipeline or network errors, so a temporary failure does not unnecessarily discard a valid account session.
- Cached profile presence is merged with live state instead of being replaced by a late stale response.
- Friend sorting, notification receipt times, and room-card collapse behavior are more consistent across lifecycle changes.
- iOS restores the selected dark theme after returning from the background.

## Desktop and packaging

The macOS application icon and Windows installer naming are aligned with the release version. Windows packaging now supports the generated MSI and the `VRCM-v<version>-setup.exe` installer when Inno Setup is available.

The release artifacts are built from the same version metadata:

- Android: `1.1.2`, version code `7`
- iOS: `1.1.2`, build `7`
- Desktop and Windows installer: `1.1.2`

## Known platform differences

- Android update downloads and clipboard link handling use Android-specific system integrations.
- The iOS archive in this release is ad-hoc packaged for testing and direct installation; App Store distribution still requires the normal signing and submission process.
- Windows EXE generation requires Inno Setup. MSI generation remains available through the Desktop packaging task.

## Upgrading from 1.1.1

Existing accounts, favorites, and settings remain available. The first launch may refresh or migrate local caches so favorite content and profile data are separated by account. Android users who want background update or notification behavior should review the relevant system permissions and battery settings after installing the preview.
