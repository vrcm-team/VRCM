# VRCM 1.1.2: What's New

**Languages / 语言 / 日本語:** [English](1.1.2.md) / [中文](1.1.2_ZH.md) / [日本語](1.1.2_JP.md)

VRCM 1.1.2 focuses on smoother everyday workflows: favorite worlds and avatars are easier to manage, every Gallery category now has an upload editor, Android updates have fewer dead ends, and temporary connection problems are less likely to interrupt an active account.

## 1. Manage favorite worlds and avatars

Favorite actions now reflect the current account before you make a change. Open a world or avatar detail page to see whether it can be added to favorites or is already saved and ready to edit.

- Add, move, or remove a world or avatar using its existing VRChat favorite groups.
- Retry directly when the favorite status cannot be loaded.
- Tap a hidden world or avatar in a favorite list to remove the unavailable entry.
- Open favorite world and avatar lists with previously viewed content already visible while VRCM checks for updates.
- Switch accounts without seeing favorites left over from the previous account.

Hidden content can only be removed because its detail page and current group information may no longer be available. VRChat's normal favorite limits and account permissions still apply.

Profile pages also retain previously loaded descriptions for created worlds and refresh changed worlds as needed. This makes repeat visits faster without replacing a newer online status with older profile information.

## 2. Prepare Gallery images before uploading

Every supported Gallery category now uses the editor before upload. Open Gallery from your profile, choose Gallery, Icon, Emoji, Sticker, or Print, then select an image to preview the final framing.

- Pan, zoom, rotate, and flip the image before submitting it.
- Choose between showing the full image and filling the target frame.
- Preserve transparent areas for Gallery, Icon, Emoji, and Sticker output.
- Fill unused Print space with white when the source does not cover the frame.
- When a previously downloaded Print is detected, turn border cropping on or off and see the result immediately.
- Use the correct landscape, square, or Print proportions for the selected category.

Successful uploads refresh the active category so the new item appears immediately. Network, permission, format, and image-size failures now produce a clear failure instead of appearing successful.

Gallery uploads require VRC+. The editor accepts JPEG and PNG, plus HEIC or HEIF where the operating system supports them. Animated files are not uploaded directly; edited output is a static PNG. Source files must be no larger than 50 MiB or 100 megapixels, and the original file is never modified.

## 3. Download updates with fewer dead ends

Android users can now continue from the update dialog directly to the system installer. VRCM selects the matching APK, shows download progress, and tries alternate download routes when GitHub cannot be reached directly.

Before opening the installer, VRCM checks that the APK belongs to the same application and uses the same signing identity as the installed copy. Android may still ask for permission to install apps from VRCM. If the download cannot be completed, the GitHub Release page opens as a fallback.

The in-app download flow is Android-only. iOS and Desktop continue to open the release page, where the platform packages use consistent 1.1.2 version numbers and file names.

Windows users can choose the EXE setup program when it is listed, with English, Simplified Chinese, Traditional Chinese, and Japanese installer text; the MSI remains an alternative. The EXE is not code-signed, so Windows SmartScreen may show an unknown-publisher warning. The macOS package now displays the VRCM app icon.

## 4. Control clipboard link detection

Clipboard detection can now be enabled or disabled from **More Settings**. It is enabled by default and, while you are signed in, recognizes supported VRChat user, world, group, and avatar links or IDs before asking whether to open them.

Ordinary clipboard text is ignored, and VRCM does not navigate without confirmation. Links just shared or copied by VRCM are also ignored when you return to the app, preventing the app from prompting for its own link. Turning the setting off does not affect manual search or links opened directly from another app.

## 5. Stay connected and keep current information visible

When VRChat rejects an expired live connection, VRCM can renew the saved sign-in and reconnect when the account is still valid. A temporary network or service failure no longer automatically signs out the current account.

Other daily-use improvements include:

- Favorite friends are ordered with in-game friends first, followed by web and offline friends.
- Profile pages retain the latest live presence while other details are refreshed.
- Android online and offline notifications with avatars show their arrival time.
- Room cards expand and collapse more smoothly.
- iOS keeps the system dark appearance after returning from the background.
- Japanese friend-location labels are clearer and more accurate.

This recovery does not bypass VRChat authentication. If the credentials are rejected or fresh verification is required, VRCM returns to the normal sign-in flow.

## 6. Platform and upgrade notes

The shared content features remain available across supported platforms; only update installation differs.

| Capability | Android | iOS | Desktop |
| --- | :---: | :---: | :---: |
| World and avatar favorite management | Yes | Yes | Yes |
| Gallery editing and upload | Yes, VRC+ required | Yes, VRC+ required | Yes, VRC+ required |
| Clipboard link detection | Yes | Yes | Yes |
| Live connection recovery | Yes | Yes | Yes |
| Update action | Download and open installer | Open release page | Open release page |

VRCM 1.1.2 is distributed as a GitHub preview release, not a store release. Existing accounts, favorites, and settings are retained; the first visit to a favorite or profile page may take a moment to refresh its saved content.

The iOS IPA is an ad-hoc package for direct testing and is not an App Store build. Windows users should expect the unsigned-EXE warning described above. On every platform, select a download whose name contains version `1.1.2`.
