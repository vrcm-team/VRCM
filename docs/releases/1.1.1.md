# VRCM 1.1.1: What's New

**Languages / 语言 / 言語:** [English](1.1.1.md) · [中文](1.1.1_ZH.md) · [日本語](1.1.1_JP.md)

This document covers the main user-facing changes from `1.0.7` to `1.1.1`. The release is not simply a longer list of profile pages. It makes VRCM a more social, more convenient VRChat companion: understand your social circles, keep a local history of time spent together, notice important activity on your phone, and move quickly from a shared link to the next game session or real-world meetup.

Compared with VRCX's focus on desktop information management and logs, VRCM emphasizes mobile social statistics, system alerts, direct game interaction, and in-person social use. This is a difference in product focus, not a claim of API, data-file, or feature compatibility.

The mobile screenshots in this document were captured on a physical OPPO Android device. The friend-network image is privacy-redacted, and the notification image contains no real friend notification content.

## Release scope at a glance

This release is best understood as a mobile social workflow rather than a collection of isolated screens:

1. **Understand relationships:** turn mutual-friend data and locally observed activity into a relationship view and a time-together history.
2. **Act from context:** move from a profile, world, notification, or copied URL to an invite, Boop, official page, or share action without restarting the search.
3. **Stay connected away from the desktop:** optionally keep Android monitoring active and receive system alerts for the events that matter to you.
4. **Carry identity and photos into the real world:** show a meetup name card, upload phone photos to VRChat+ Gallery, and send Gallery images through the phone's normal sharing tools.

The app does not recreate VRChat's complete server-side history. Activity statistics begin with what VRCM can observe, and system alerts remain subject to operating-system permissions, background restrictions, and account access.

## 1. Understand your network and remember time together

### Friend network

Open the action menu on your own profile and choose **View Friend Network**. VRCM builds an interactive graph from mutual-friend relationships.

- **Community view** groups closely connected friends into social circles, using color and boundaries to make the structure easier to read.
- **Ego view** highlights connections around you and ranks friends with the most mutual connections.
- Zoom, pan, and select nodes to inspect mutual friends. The top-bar refresh action requests new relationship data; when a network request is not needed yet, the screen can start from its local cache.
- The graph cache is scoped to the signed-in account. Switching accounts does not merge one account's friends into another account's graph.
- The current release intentionally keeps the graph as an in-app analysis view. The old **save/export graph image** action was removed in `16b7efa` so the screen no longer presents a misleading export path.

The network represents connections inferred from VRChat mutual-friend data. It does not measure real-world closeness. Friend avatars and display names in the screenshot have been fully redacted.

#### How to read the two views

- **Community view** groups the graph into colored regions. Selecting a region highlights the corresponding set of nodes so a dense network can be read as several smaller circles.
- **Ego view** puts the user's immediate network first and provides a ranked list of friends with the most mutual connections. Selecting a friend highlights that friend and the adjacent connections.
- The graph remains interactive while the data is cached. A loading or preparation state is shown during a refresh rather than replacing the old result with an empty canvas.

### Friend activity and time-together statistics

Friend profiles now summarize social data observed locally by VRCM:

- last meeting time, meeting count, and total time played together;
- friends you recently played with;
- online, offline, world-change, status-change, and bio-change events;
- timelines for entering and leaving the same instance;
- world names, instance access types, and bio-change diffs.

This data is stored per account in the local database and is not uploaded to a VRCM-operated server. Statistics cover only activity VRCM observed while it was running. Android can continue observing when optional background monitoring is enabled. This is not a complete history supplied by VRChat, and it cannot reconstruct activity from before VRCM was installed.

The time-together calculation is deliberately conservative: it is based on overlapping, observed presence in the same instance and the activity events available to VRCM. It should be read as a useful personal summary, not as an attendance record or a claim about time spent actively interacting.

## 2. Turn discovery directly into interaction

VRCM connects common mobile interactions to profile, world, and notification flows:

- inspect a friend's instance and invite yourself to join;
- send default, heart, wave, laugh, like, thinking, surprise, or angry Boops;
- handle friend requests, invitations, and Boop replies from the notification center;
- explore mutual friends, mutual groups, and a user's created worlds or avatars;
- edit your own status, status description, bio, pronouns, languages, and social links;
- share official VRChat user, world, group, and avatar URLs through the system share sheet.

The goal is to shorten the path from finding a person or world to actually interacting, rather than only reproducing information pages on a phone.

### A typical mobile interaction loop

1. Open a friend's profile from the friend list, a notification, a mutual-friend result, or a copied link.
2. Check the current instance and world context before choosing an action.
3. Invite yourself, send a Boop, open the official VRChat page, or share the link through the system sheet.
4. Return to VRCM's notification center to handle a response without losing the profile or world context.

This flow is intentionally action-oriented. It does not automatically join a room, send a friend request, or navigate from clipboard content without a confirmation step.

## 3. Copy a link and continue in VRCM

VRChat links often arrive through chats, browsers, and group conversations. Copy one of the following, return to VRCM, confirm the prompt, and VRCM resolves it directly to the matching page:

- User: `https://vrchat.com/home/user/usr_...` or `usr_...`
- World: `https://vrchat.com/home/world/wrld_...` or `wrld_...`
- Group: `https://vrchat.com/home/group/grp_...` or `grp_...`
- Avatar: `https://vrchat.com/home/avatar/avtr_...` or `avtr_...`

VRCM accepts only exact supported formats from `https://vrchat.com` or `https://www.vrchat.com`. It always asks before navigating and never silently opens a target just because it appeared in the clipboard. Android can also receive these official links directly through the system's **Open with** flow.

A typical flow is: copy a world URL from a chat, return to VRCM and confirm, inspect the world and active instances, then invite yourself to join. User, group, and avatar links work without a manual search as well.

The supported input is deliberately narrow. VRCM accepts the official VRChat host formats and known identifiers (`usr_`, `wrld_`, `grp_`, and `avtr_`); unrelated clipboard text is ignored. If the target cannot be resolved, the user sees an error result and remains on the current page. Android also declares the supported official web-link route so the system can offer VRCM in its **Open with** chooser.

## 4. A two-way workflow between your phone and VRChat+ Gallery

Gallery is no longer only a viewer for game screenshots. It connects the phone's photo library and VRChat in both directions.

### Upload phone photos to VRChat

- Use one upload entry across Gallery, Icon, Emoji, and Print categories.
- Android and iOS open the system image picker; Desktop opens a local file picker.
- Regular Gallery uploads support JPEG, PNG, GIF, and WebP.
- Print uploads support JPEG, PNG, and HEIC/HEIF, and open a crop-and-preview editor before uploading.
- The current category refreshes automatically after a successful upload.

Selected content is sent directly from the device to VRChat and is not proxied through a VRCM-operated server. The Gallery upload entry requires VRC+ on the current VRChat account.

The upload flow is intentionally separated from the photo-management flow:

- selecting a phone image opens the platform picker and keeps the original selection local until the upload is confirmed;
- Print images pass through a crop-and-preview editor, so the user can choose the composition before sending it;
- after a successful upload, the active category refreshes so the new item can be verified immediately;
- an account without VRC+ can browse eligible content such as Prints, but the upload action is rejected by the same entitlement boundary used by VRChat.

### Save game photos to your phone and share them quickly

Open a photo taken in-game and synced to Gallery, then use the save action to write it to the Android or iOS system photo library. Desktop saves it under the `VRCM` folder in the user's Pictures directory. Once it is on your phone, share it immediately through the system gallery, a messaging app, or a social app.

VRCM also supports zoomed previews, file counts by category, long-press multi-selection, and batch deletion. Users without VRC+ can still view Prints, but cannot use the Gallery upload entry.

### Share an image directly from the preview (`16b7efa`)

The final 1.1.1 update adds a separate **Share image** action to the full-screen image preview. This is different from **Save image**:

- **Share image** downloads the original file endpoint and hands it to the native Android or iOS share sheet. A user can send the image to a chat, social app, cloud drive, or file manager without first creating a second photo-library copy.
- **Save image** writes the image to the Android/iOS system photo library, or to `Pictures/VRCM` on Desktop. Once saved, the platform's photo app can be used for later sharing.
- The on-screen preview continues to use a bounded image URL to reduce memory use; share and save use the original file URL so the shared/saved result is not the lower-resolution preview.
- Both operations have their own loading state and failure feedback. A missing share target, a failed download, or a denied photo-library operation is reported instead of being treated as success.

On Android the share file is staged in an app-private cache and exposed with a temporary `FileProvider` read grant. On iOS the image is passed to `UIActivityViewController`. Desktop keeps image saving but does not claim to provide a native image share sheet yet. The direct share action does not require an extra VRCM account export or a VRCM-operated media server.

## 5. Android system alerts and background social awareness

Android now has dedicated notification settings and optional background monitoring, helping you notice relevant activity even after leaving VRCM.

- Control friend online and offline alerts independently.
- Build **Exclude selected** or **Only selected** rules from favorite friend groups.
- Override favorite friends individually with **Follow group**, **Always**, or **Never**.
- Receive alerts for every Boop, friend request, group announcement, event, or moderation message.
- Be notified when VRChat reports a service incident or recovery.
- Check notification permission and jump directly to app-management or battery-management settings.

<div align="center">
  <img src="../../image/Feature-Android-Notifications.png" width="360" alt="Android notification and background-monitoring settings on a physical phone"/>
</div>

Background monitoring is opt-in. Android 13 and later also require notification permission, and some device vendors may require VRCM to be allowed in battery settings. iOS and Desktop do not provide this Android foreground service or its system alerts.

In-app notifications have also moved from a Home overlay into a dedicated notification center with restored real-time delivery and actions. System alerts show the actual receipt time, and friend-request or activity alerts use the correct display name and avatar whenever possible.

### Notification behavior and limits

- Online/offline rules are evaluated against favorite groups and per-friend overrides; changing a rule affects future observations and does not replay the entire cached history.
- Boop, friend-request, group, and service-status categories can be controlled separately. A disabled category does not silently become an in-app event later.
- The foreground service depends on Android's service and battery policies. VRCM exposes the relevant app-management and battery-management destinations, but the operating system and device vendor ultimately decide whether a background process can continue.
- Notification content is generated from the event VRCM received. It is not a substitute for the VRChat mobile app's own notification history.

## 6. Turn your phone into a meetup name card

Long-press your avatar on Home to open a name card designed for holding up your phone at a VRChat meetup, helping others recognize you and exchange profile or social links.

- **Three templates:** Info Bar, Spotlight, and Side Tag.
- **Two orientations:** portrait and landscape keep independent layouts and photo crops.
- **Multiple photo sources:** VRChat profile background, phone photo library, or VRChat Gallery.
- **Optional identity fields:** avatar, pronouns, languages, status, status description, custom short text, and primary group.
- **VRChat visual identity:** avatar frame, profile effect, and nameplate effect.
- **QR codes:** show a VRChat profile and profile social links together, up to four codes with short labels.
- **On-site presentation:** keep the display awake in full screen, switch orientation quickly, or save the finished card as an image.

<div align="center">
  <img src="../../image/Feature-Meetup-Card.png" width="360" alt="Full-screen meetup name card on a physical phone"/>
</div>

QR codes use a standard VRChat web profile or links configured on the user's profile. The other device does not need VRCM installed. Complete the editor once on first use; later, long-pressing the avatar opens the display directly.

The name card is designed for a short in-person exchange rather than permanent profile replacement. QR codes point to the standard VRChat web profile or links configured on the profile, so the other person can use a normal camera or QR reader and does not need VRCM installed. The selected photo and layout are stored locally with separate portrait and landscape crops. Saving the finished card creates an image in the system gallery; it does not publish the card back to VRChat.

## 7. Other notable updates

These are not the main product story of this release, but they are also complete since `1.0.7`:

- redesigned user profiles with created worlds, created avatars, favorite worlds, mutual groups, and recently visited worlds;
- a new avatar-detail screen for switching or copying available avatars and editing the name, description, or cover of avatars you uploaded;
- group posts, members, galleries, group instances, and group search;
- local caching and incremental background refresh for worlds, user profiles, groups, friend lists, and relationship data;
- Navigation 3 migration with adaptive two-pane layouts, state restoration, shared transitions, and improved Desktop windows;
- platform secure storage for account credentials and Room storage for profile and activity caches;
- stronger rate-limit retry, WebSocket reconnection, account-switch isolation, and foreground/background recovery.

## Upgrading from 1.0.7

- The current app version is `1.1.1` (version code 6).
- Existing accounts, favorites, and settings remain available; cache structures migrate or rebuild on first launch.
- The friend-network screen no longer offers graph-image export. Existing cached relationship data remains usable in the in-app graph.
- Gallery image preview now has separate share and save actions. Sharing uses the original image and the platform share sheet; saving keeps the existing photo-library/Pictures behavior.
- The meetup-card schema changed during development. Incompatible configurations from early development builds may need to be configured again. Official `1.0.7` users did not have this feature and are unaffected.
- To use Android system alerts, grant notification permission. To continue statistics and alerts in the background, also enable background monitoring under **Settings → Notification Settings**.
