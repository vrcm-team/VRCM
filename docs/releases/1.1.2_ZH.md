# VRCM 1.1.2 新功能详解

**Languages / 语言 / 言語:** [English](1.1.2.md) · [中文](1.1.2_ZH.md) · [日本語](1.1.2_JP.md)

本文汇总从 `1.1.1` 到 `1.1.2` 的主要用户可见变化。本次更新的重点不是增加一组彼此孤立的列表，而是把收藏内容、Gallery 编辑、Android 更新和实时会话恢复这些日常流程做得更可靠：进入详情页时看到正确的收藏状态，上传照片前看清最终构图，服务变化后尽量恢复当前账号，多个平台的产物也使用同一套版本信息。

## 版本重点

这个版本可以看作四条相互连接的使用流程：

1. **让收藏内容保持正确**：好友、世界和模型相关缓存跟随当前账号，迟到的请求不会覆盖新状态。
2. **在发送图片前完成准备**：Gallery 和 Print 编辑器让白边、裁剪、格式和输出大小都能在上传前确认。
3. **服务变化时继续使用应用**：Android 更新支持镜像回退，剪贴板读取可配置，过期实时会话可以进入认证恢复流程。
4. **让各端使用同一版本**：Android、iOS、Desktop 和 Windows 安装包的版本与发布命名保持一致。

## 1. 让收藏内容与缓存保持一致

### 收藏世界与收藏模型

只有收藏状态、所属分组和详情页描述的是同一个账号，收藏才真正有用。1.1.2 补齐了收藏世界与收藏模型从查看到管理的完整流程：

- 打开世界或模型详情时，可以先看到当前账号是否已经收藏，再决定下一步操作；
- 把内容加入已有分组或本地分组后，刷新分组列表不会丢掉刚刚修改的项目；
- 在多个分组存在相似内容时，删除操作仍会定位到正确的收藏记录；
- 可以查看和移除隐藏世界、隐藏模型，不会把隐藏内容混入正常收藏分组；
- 明确区分世界、模型和好友三种收藏类型，避免把一种 ID 写入另一种缓存。

本地分组是 VRCM 为本机观察到的内容提供的账号内便利功能，并不等同于 VRChat 服务器上的新分组。远程分组仍然遵循 VRChat 收藏 API 和当前账号的权限。

### 账号隔离与刷新时序

用户切换账号或离开详情页时，收藏和资料请求可能仍在进行。本次更新明确了每个请求属于哪个账号和目标：

- 旧账号的响应不能覆盖当前账号的收藏状态；
- 目标被清空后，进行中的加载会失效，不会把旧目标重新显示回来；
- 收藏状态加载失败会显示可重试状态，而不是静默地当成“未收藏”；
- 资料缓存收到实时在线状态后，较慢的资料响应不会把新状态覆盖掉；
- 用户资料和创建世界支持增量刷新，减少每次进入页面时整块替换缓存的情况。

这不是把本地缓存当成第二个服务器。缓存过期或操作需要最新数据时，VRCM 仍会向 VRChat 请求；缓存只是稳定的起点，最终状态仍以服务器结果为准。

## 2. 在上传前完成 Gallery 图片编辑

### Print 与拍立得白边流程

Print 图片经常需要先调整构图，而不是直接把原文件上传到 VRChat。现在编辑器可以在一个流程中完成这些决定：

- 当原图没有合适留白时，为 Print 增加白边；
- 在预览最终效果时裁剪拍立得白边，不必上传后才发现构图不对；
- 编辑过程中切换裁剪行为，并立即看到预览变化；
- Gallery、Icon、Emoji 和 Print 使用各自正确的输出比例，不再把所有分类套用同一个矩形。

图片选择和上传请求仍然分开。用户可以在最后提交前取消或返回，不会留下半完成的 Gallery 项目。

### 格式、透明度与内存边界

图片处理流程现在会保留影响最终文件质量的属性：

- 在目标格式支持时保留透明度；
- 编码时遵循用户选择的格式和当前分类的输出限制；
- 对不支持的格式、过大的文件和超过像素上限的图片明确报错；
- 使用有边界的尺寸解码和裁剪，避免大图占用不可控的内存；
- 裁剪完成或提交失败后释放中间 Bitmap 和预览资源。

这些限制属于上传契约的一部分。它们避免出现“预览看起来成功、最终上传却被 VRChat 拒绝”的情况，同时不会修改设备上的原始文件。

### 上传、取消与错误状态

Gallery 现在分别处理选择、准备、上传、刷新、取消和失败。上传成功后会刷新当前分类，用户可以立即确认新项目；网络错误、权限错误、格式错误或取消操作都会显示为对应结果，不会伪装成成功。

## 3. Android 更新与剪贴板链接

### 应用内更新下载

Android 更新下载现在由 VRCM 负责完整的下载步骤：

- 更新弹窗只选择 Android APK，不会把其他平台的包交给 Android；
- 下载器会检查配置好的来源，GitHub 地址不可用时可以切换镜像；
- 进度和取消状态绑定实际的 Android `DownloadManager` 请求；
- 失败或取消后清理临时文件和下载状态，下一次更新可以从已知状态重新开始。

镜像是下载回退，并不是 GitHub Release 的替代品。VRCM 仍然选择 Release 中的 APK 资产，安装时也继续遵循 Android 的安装权限边界。

### 可配置的剪贴板读取

剪贴板读取现在是设置项，对支持的官方 VRChat URL 和 ID 默认开启。VRCM 仍会在跳转前询问，只识别受支持的 VRChat 格式，普通文本不会被当成链接处理。

剪贴板检查器还会记录刚刚由 VRCM 发出的链接。用户从系统分享面板返回后，应用不会把自己复制的 URL 再当成新的外部链接。关闭该设置不会影响手动搜索或直接导航。

## 4. 尽量恢复会话，而不是直接丢弃账号

### 过期的实时会话

VRChat 实时会话可能在应用进入后台或网络路径变化时过期。现在 VRCM 会区分“会话被拒绝”和“临时管线/网络错误”：

- 账号仍然有效时，过期会话可以进入既有认证恢复流程并重新连接；
- 临时传输或管线错误不会自动清除当前账号；
- WebSocket 状态会单独报告会话拒绝原因，不会把所有异常都归为未知处理错误；
- 从后台回到前台时，可以恢复实时流，不必重建无关的资料和收藏页面。

这不是绕过 VRChat 登录。如果账号需要重新登录或服务器拒绝凭据，VRCM 会明确停在认证边界，并交给正常登录流程处理。

### 生命周期与通知细节

下面这些看似较小的修复保护的是同一套状态契约：

- 好友动态刷新期间收到在线状态时，排序不会突然跳动；
- 资料缓存接收实时状态后，不会被迟到的旧响应覆盖；
- 通知时间显示实际接收时间，而不是无关的界面重绘时间；
- 房间卡片在生命周期切换后不容易留下过期的收起动画状态；
- iOS 从后台返回后会恢复已选择的深色主题。

## 5. 多端使用同一套版本信息

发版脚本会同步 Version Catalog、Inno Setup、Xcode 工程和 iOS `Info.plist`。本次 1.1.2 产物使用以下版本信息：

| 产物 | 版本 | 构建号 |
| --- | ---: | ---: |
| Android APK | 1.1.2 | 7 |
| iOS IPA | 1.1.2 | 7 |
| macOS Desktop DMG | 1.1.2 | 1.1.2 |
| Windows MSI / EXE 安装包 | 1.1.2 | 1.1.2 |

Windows 会保留 Compose Desktop 生成的 MSI；安装了 Inno Setup 时还可以额外生成 `VRCM-v<version>-setup.exe`。macOS 使用 VRCM 应用图标，产物名称也足够稳定，可以交给发布脚本和更新检查继续使用。

## 6. 平台差异与边界

| 能力 | Android | iOS | Desktop |
| --- | :---: | :---: | :---: |
| 收藏世界与收藏模型管理 | 支持 | 支持 | 支持 |
| Gallery 与 Print 编辑 | 支持 | 支持 | 支持 |
| 应用内 APK 更新下载 | 支持 | 不适用 | 不适用 |
| 剪贴板 URL/ID 识别 | 支持 | 支持 | 支持 |
| 实时会话恢复 | 支持 | 支持 | 支持 |
| macOS DMG 打包 | 不适用 | 不适用 | 支持 |
| Windows MSI/EXE 打包 | 不适用 | 不适用 | 仅 Windows |

本次预览版中的 iOS IPA 使用 ad-hoc 方式打包，适合直接测试，不代表 App Store 提交包；正式分发仍需要正常的 Apple 签名、描述文件和提交流程。Windows EXE 需要安装 Inno Setup，MSI 打包任务不依赖这个可选编译器。

## 7. 其他值得关注的修复

下面这些改动不如前面的流程集中，但会影响重复使用：

- 修复 Gallery 上传失败、动画图片处理、输出比例和图片编辑器布局切换；
- 修复收藏删除定位、详情页收藏状态和账号切换后的缓存失效；
- 修复 Android 更新取消流程与镜像回退异常；
- 修复 iOS 深色主题恢复和好友位置页日语文案；
- 修复应用分享链接触发自身剪贴板提示、通知显示数据和多处生命周期切换问题；
- 统一 macOS 图标与 Windows 安装包的版本命名。

## 从 1.1.1 升级

- 当前应用版本为 `1.1.2`，Android/iOS version code 为 `7`；
- 原有账户、收藏和设置会继续保留，首次启动可能需要刷新或迁移本地缓存；
- 收藏和资料缓存现在按账号隔离得更严格。升级后如果列表暂时不完整，请先等待首次刷新完成再重复操作；
- Android 用户如需更新下载或系统通知，请检查通知、安装和耗电管理权限；
- 本次 GitHub 预览版中的 iOS IPA 与 Desktop DMG 用于直接安装测试，不代表 App Store 提交包，也不保证每台 Windows 机器都能直接运行签名 EXE。
