# VRCM 1.1.2 新機能の詳細

**Languages / 语言 / 言語:** [English](1.1.2.md) · [中文](1.1.2_ZH.md) · [日本語](1.1.2_JP.md)

このドキュメントでは、`1.1.1` から `1.1.2` までの主なユーザー向け変更をまとめています。今回の更新は、フレンドやワールドを保存して使う流れ、Gallery の画像編集、Android の更新ダウンロード、リアルタイムセッションの復旧を安定させるためのリリースです。複数のプラットフォームでも同じバージョン情報と成果物命名を使用します。

## このリリースの範囲

今回の変更は、次の4つのつながったワークフローとして見ることができます。

1. **保存したコンテンツを正しく保つ**：お気に入りと非表示項目を現在のアカウントに紐づけ、古いリクエストが新しい状態を上書きしないようにします。
2. **送信前に画像を仕上げる**：Gallery と Print の編集画面で、白い余白、トリミング、形式、出力サイズを確認できます。
3. **サービスの状態が変わっても使い続ける**：Android の更新はミラーへフォールバックでき、クリップボード監視は設定で変更でき、期限切れのセッションは認証フローから復旧できます。
4. **すべてのプラットフォームで同じリリースにする**：Android、iOS、Desktop、Windows のバージョンと成果物名を統一します。

## 1. お気に入りとキャッシュを正しく同期する

### ワールドとアバターのお気に入り

お気に入りの状態、所属するグループ、詳細画面が同じアカウントを示して初めて、保存したコンテンツは役に立ちます。1.1.2 ではワールドとアバターについて、確認から管理までの流れを整理しました。

- ワールドやアバターの詳細画面で、操作する前に現在のアカウントのお気に入り状態を確認できます。
- 既存のグループまたはローカルグループへ追加した後も、グループ一覧を更新して追加した項目を失いません。
- 似た項目が複数のグループにあっても、正しいお気に入りレコードを削除します。
- 非表示ワールドと非表示アバターを確認・削除できます。通常のお気に入りグループへ混ざることはありません。
- ワールド、アバター、フレンドの種類を明確に分け、異なるキャッシュへ ID を書き込まないようにします。

ローカルグループは、VRCM が端末上で確認した項目を扱うためのアカウント単位の便利な場所です。VRChat サーバー上の新しいグループではありません。リモートグループは引き続き VRChat の API とアカウント権限に従います。

### アカウント分離と更新

アカウントを切り替えたり詳細画面を離れたりした後も、前のリクエストが残っている場合があります。このリリースではリクエストの所有者を明確にしました。

- 前のアカウントのレスポンスが、現在のアカウントのお気に入り状態を置き換えません。
- 対象が空になった場合、進行中の読み込みを無効にし、古い対象を再表示しません。
- お気に入り状態の読み込み失敗は「未お気に入り」として隠さず、再試行できる状態で示します。
- 遅いプロフィールレスポンスが、キャッシュに反映済みのオンライン状態を上書きしません。
- ユーザープロフィールと作成ワールドは可能な場合に増分更新し、毎回全体を置き換えません。

キャッシュをサーバーの代わりにする変更ではありません。キャッシュが古い場合や最新データが必要な操作では、VRCM は引き続き VRChat へ問い合わせます。

## 2. Gallery の画像をアップロード前に編集する

### Print と Polaroid の余白編集

Print 画像は、元ファイルをそのまま送るのではなく構図を整えたい場合があります。編集画面で次の操作を一つの流れとして行えます。

- 元画像に余白がない場合、Print に白い余白を追加します。
- 結果を確認しながら Polaroid の余白をトリミングできます。
- 編集中にトリミング方法を切り替え、プレビューの変化をすぐ確認できます。
- Gallery、Icon、Emoji、Print それぞれの出力比率を使い、全カテゴリへ同じ矩形を適用しません。

画像の選択とアップロードリクエストは分離されています。最後の送信前にキャンセルしても、途中の Gallery 項目が残りません。

### 形式、透明度、メモリ制限

画像処理は、編集結果を別の場所でも使えるように次の条件を守ります。

- 出力形式が対応している場合は透明度を維持します。
- 選択した形式とカテゴリ固有の出力制限に従ってエンコードします。
- 未対応形式、サイズ超過、ピクセル上限超過を明確なエラーとして示します。
- 大きな画像を無制限に展開しないよう、上限のあるサイズでデコードとトリミングを行います。
- トリミング完了後や送信失敗後に中間 Bitmap とプレビュー用リソースを解放します。

これらはアップロードの契約の一部です。プレビューだけ成功して VRChat 側で拒否される状態を減らし、端末上の元ファイルは変更しません。

### アップロードと失敗状態

Gallery は、選択、準備、アップロード、更新、キャンセル、失敗を別々の状態として扱います。アップロード成功後は現在のカテゴリを更新し、すぐに新しい項目を確認できます。ネットワーク、権限、形式、キャンセルの結果を成功として表示することはありません。

## 3. Android の更新とクリップボードリンク

### アプリ内更新ダウンロード

Android の更新ダウンロードは、VRCM 内で完了する流れになりました。

- 更新ダイアログは Android 用 APK を選び、別プラットフォームの成果物を表示しません。
- GitHub のエンドポイントが利用できない場合、設定されたミラーを試します。
- 進捗とキャンセルは Android の実際の `DownloadManager` リクエストに結び付きます。
- 失敗またはキャンセルした場合、一時ファイルとダウンロード状態を整理し、次回は既知の状態から始めます。

ミラーは配信のフォールバックであり、GitHub Release の代わりではありません。VRCM は Release の APK アセットを選択し、インストール時は Android の通常の権限境界に従います。

### クリップボード監視の設定

クリップボード監視は設定項目になり、対応する公式 VRChat URL と ID に対して初期状態で有効です。移動前には確認を表示し、対応形式以外の一般的なテキストはリンクとして扱いません。

VRCM がシステム共有で直前に作成した URL も記録します。共有シートから戻ったとき、自分でコピーした URL を新しい外部リンクとして再処理しません。監視を無効にしても手動検索や直接ナビゲーションは利用できます。

## 4. セッションを破棄せずに復旧する

### 期限切れのリアルタイムセッション

アプリがバックグラウンドに入ったりネットワーク経路が変わったりすると、VRChat のリアルタイムセッションが期限切れになることがあります。VRCM は、セッション拒否と一時的なパイプラインエラーを区別します。

- アカウントが有効であれば、期限切れセッションは既存の認証回復フローから再接続できます。
- 一時的な通信またはパイプラインエラーだけで、現在のアカウントセッションを削除しません。
- WebSocket の状態は、セッション拒否の理由を予期しない処理エラーと分けて報告します。
- フォアグラウンドへ戻ったとき、無関係なページのキャッシュを作り直さずにリアルタイムストリームを復元できます。

これは VRChat の認証を回避するものではありません。再ログインが必要な場合や資格情報が拒否された場合は、認証の境界を明確にして通常のログインフローへ渡します。

### ライフサイクルと通知

次の小さな修正も、同じ状態契約を守るためのものです。

- プレゼンス更新がリフレッシュ中に届いても、フレンドの並び順が不安定になりません。
- キャッシュ済みプロフィールへリアルタイム状態を反映した後、遅い古いレスポンスで置き換えません。
- 通知時刻は、関係のない画面再描画時刻ではなく受信時刻を示します。
- ライフサイクル切り替え後にルームカードの古い折りたたみアニメーションを残しにくくします。
- iOS はバックグラウンドから戻った後も選択したダークテーマを復元します。

## 5. すべてのプラットフォームで同じバージョン

リリーススクリプトは Version Catalog、Inno Setup、Xcode プロジェクト、iOS の `Info.plist` を同期します。1.1.2 の成果物は次のメタデータで作成されています。

| 成果物 | バージョン | ビルド番号 |
| --- | ---: | ---: |
| Android APK | 1.1.2 | 7 |
| iOS IPA | 1.1.2 | 7 |
| macOS Desktop DMG | 1.1.2 | 1.1.2 |
| Windows MSI / EXE インストーラー | 1.1.2 | 1.1.2 |

Windows では Compose Desktop が作成する MSI を使い、Inno Setup がインストールされている場合は `VRCM-v<version>-setup.exe` も作成できます。macOS パッケージは VRCM のアプリアイコンを使い、成果物名はリリース自動化と更新確認で扱いやすい形式に揃えています。

## 6. プラットフォーム差異と境界

| 機能 | Android | iOS | Desktop |
| --- | :---: | :---: | :---: |
| ワールド・アバターのお気に入り管理 | 対応 | 対応 | 対応 |
| Gallery と Print の編集 | 対応 | 対応 | 対応 |
| アプリ内 APK 更新ダウンロード | 対応 | 対象外 | 対象外 |
| クリップボード URL/ID 認識 | 対応 | 対応 | 対応 |
| リアルタイムセッション復旧 | 対応 | 対応 | 対応 |
| macOS DMG パッケージ | 対象外 | 対象外 | 対応 |
| Windows MSI/EXE パッケージ | 対象外 | 対象外 | Windows のみ |

今回のプレビュー版 iOS IPA は直接テスト用の ad-hoc パッケージです。App Store 配布には通常の Apple 署名、プロビジョニング、提出手続きが必要です。Windows EXE の作成には Inno Setup が必要ですが、Desktop の MSI タスクはこのオプションコンパイラに依存しません。

## 7. その他の修正

日常の繰り返し利用に関わる、その他の主な修正です。

- Gallery のアップロード失敗、アニメーション画像処理、出力比率、画像編集画面のレイアウト切り替えを修正。
- お気に入り削除の対象、詳細画面のお気に入り状態、アカウント切り替え後のキャッシュ無効化を修正。
- Android 更新のキャンセル処理とミラーへのフォールバックエラーを修正。
- iOS のダークテーマ復元とフレンド位置ページの日本語表示を修正。
- 自分で共有したリンクによるクリップボード通知、通知表示データ、複数のライフサイクル切り替えを修正。
- macOS アイコンと Windows インストーラー名をリリースバージョンに統一。

## 1.1.1 からのアップグレード

- 現在のアプリバージョンは `1.1.2`、Android/iOS の version code は `7` です。
- 既存のアカウント、お気に入り、設定は保持されます。初回起動時にローカルキャッシュの更新または移行が行われる場合があります。
- お気に入りとプロフィールのキャッシュはアカウントごとに厳密に分離されます。アップグレード直後に一覧が不完全に見える場合は、最初の更新が終わるまで待ってください。
- Android で更新ダウンロードやシステム通知を使う場合は、通知、インストール、バッテリー管理の権限を確認してください。
- GitHub プレビュー版の iOS IPA と Desktop DMG は直接インストール用のテスト成果物です。App Store 提出用ではなく、すべての Windows 環境で署名済み EXE が実行できることを保証するものでもありません。
